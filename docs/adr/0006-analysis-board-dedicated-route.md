# 0006 — 分析画板独立路由化

> 本文已被 [0007](0007-analysis-board-becomes-test-design-canvas.md) 修订：画板从只读阅览进化为可编辑测试设计画布。

## 状态

已接受（部分被 0007 修订）

## 背景

ADR 0005 把结果视图改为全屏分析画板，但画板仍是 `RequirementAnalysisPage` 内的同页状态（`phase === 'result'`）：URL 不变、刷新即丢、无法收藏或分享直达链接。对标 boardmix 白板编辑器"每个画板一个 URL"的形态，画板需要独立路由。同时，画板后续将支持画布内编辑，"重新分析"入口（丢弃当前结果回到输入态）与可编辑画布的产品方向冲突，一并移除。

## 决策

- 画板路由为 `/requirement-analysis/board/:id`，由独立的 `AnalysisBoardPage` 承载，按 `:id` 自行调用 `getAnalysisRecord` 拉取数据；刷新、收藏、URL 直达均有效。
- **先存后跳**：新分析完成后先 `createAnalysisRecord` 拿到记录 id，再 `navigate` 到画板路由；保存失败则降级为留在分析进度弹窗并提示错误，不跳转（避免直达路由拿不到数据）。
- 打开记录 = `navigate` 到画板路由，数据加载职责从列表页移到画板页。
- 返回列表 = `navigate('/requirement-analysis')`；ESC 快捷键保留，行为同返回。
- 画板交互状态（图表类型、选中节点、激活结论）由画板页持有，离开路由即丢弃；图表类型切换仍回写记录 `chartType`。
- 移除"重新分析"功能：`AnalysisBoard` 右侧工具栏的重新分析按钮与 `onReanalyze` prop 删除。后续画布本身可编辑，不再需要"丢弃重来"入口。
- `RequirementAnalysisPage` 回归"记录列表 + 新建分析弹窗"两层结构，不再持有结果态。

## 备选方案

- **画板保持同页状态、仅同步 URL（query/paths 仅作展示）**：刷新后仍需从列表重新进入，直达形态名不副实，否决。
- **保存失败也跳转、画板页内重试**：画板页需要额外承载"无记录"的临时态与重试逻辑，复杂度高于留在进度页提示，否决。
- **保留"重新分析"作为画板内动作**：与可编辑画布方向冲突（编辑中的画布被重新分析覆盖是不可逆损失），否决。

## 后果

- 画板获得可分享、可刷新、可直达的 URL；浏览器前进/后退自然映射"列表 ↔ 画板"导航。
- `AnalysisBoardPage` 承担数据拉取与画板交互状态；`RequirementAnalysisPage` 精简约 120 行。
- 分析过程流式展示（processBlocks）只在分析进行中可见；从画板直达打开记录时"分析过程"抽屉为空，与原"打开记录"行为一致。
- 已保存记录的 `chartType` 在画板内切换时静默回写，语义不变。
