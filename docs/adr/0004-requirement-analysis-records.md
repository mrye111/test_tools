# 0004 — 需求分析结果从不持久化改为持久化分析记录

## 状态

已接受

## 背景

需求分析工具原设计为"分析结果不持久化"：分析在会话内一次性完成，导出文件即交付物，页面关闭后结果不保留。用户提出需要"分析记录"，形态与测试用例界面（项目列表 ↔ 用例集，后端 JSON store 持久化）一致。

## 决策

- 新增持久化的**分析记录**：每次分析成功完成后自动存入后端 JSON store（复用测试用例 store 的重试/防抖落盘模式），需求分析页改为"记录列表 ↔ 结果视图"两层结构，列表形态对齐测试用例集表格（名称/时间/结论统计/操作/分页）。
- 记录内容：名称（上传文件取文件名、粘贴文本取首行前 20 字、可重命名）、需求原文、需求分解树、分析结论、当前图表类型（打开后切换即更新）、时间。思考过程不存（术语表已有约束）。
- 只保存完成态：分析中途关闭或断流视为放弃，不产生记录；不做"分析中/失败/重试"状态机（那是独立的可重试需求，不在本期）。
- 删除记录前轻量确认，对齐删除用例语义。
- 术语表同步修订：删除"分析结果不持久化"条款，新增"分析记录"词条。

## 备选方案

- **localStorage 持久化**：换电脑/清缓存即丢，与"和测试用例界面一样"的要求不符，否决。
- **只存元数据**：无法恢复结果视图回看，否决。
- **存分析中/失败态并重试**：SSE 流式续传语义复杂，作为独立需求以后单独立项。

## 后果

- 需求分析工具从"一次性会话工具"变为"记录型工具"，与测试用例侧语义完全对齐。
- 后端 requirement 模块新增 store 与记录 CRUD 路由；新增 `server/data/` 下的分析记录数据文件。
- 接力到用例生成的入口在记录回看视图中保持可用（因记录包含需求原文）。
- 2026-07 补充：新建分析的输入与进度从独立子页面改为记录列表上的弹窗（ModalShell），"列表 ↔ 结果"两层结构与完成自动入库语义不变；全站页面容器统一为设计令牌 `--container-shell: 1440px`（宽屏封顶居中、两侧留白一致，规则 `min(100% - 32px, 1440px)`，覆盖测试用例/需求分析/JMeter/测试报告/设置/数据工厂/报告查看及首页 Hero、工具矩阵、Footer）。
