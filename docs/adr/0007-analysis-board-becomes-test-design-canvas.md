# 0007 — 分析画板进化为测试设计画布

## 状态

已接受

## 背景

ADR 0005 与 0006 落地后，分析画板 `/requirement-analysis/board/:id` 成为需求分析记录的全屏结果视图，但只支持需求分解树的阅览与导出。用户持续以 boardmix 等在线白板编辑器为对标，要求画板从"只读结果页"工作台化为可编辑的测试设计工作台；同时，测试用例设计方法中的"黑盒三件套"——因果图、判定表、正交表——需要统一、形式化的图表载体，以便从分析产物确定性推导到用例骨架。

因此，分析画板需要进化为**测试设计画布**：以需求分解树为参考起点，在自由白板上插入因果图、判定表、正交表，经 AI 生成草稿与确定性推导后，将结果接力到现有 AI 用例生成管线。

## 决策

- 分析画板形态升级为**测试设计画布**，本期为单一自由白板（无限画布 + 图元自由摆放），不引入多页签或分区画布。
- 画布渲染采用 **Canvas 2D 全量渲染**（含表格型图元），所有图元命中检测、选中态、拖拽、文本编辑由画布引擎自研；DOM overlay 仅用于文本编辑态的输入框。
- 画布引擎采用**模型与渲染分离**架构：白板模型为纯数据对象，渲染器只读模型；所有修改通过命令对象进入命令栈，再改模型、标脏、触发重绘。撤销、重做、持久化、单测均依赖该架构。
- AI 生成图表草稿时，**上下文基于需求树参考图上选中的节点**；未选中节点时插入按钮禁用。后端按 chartKind 的 prompt 契约调用 AI，输出严格 JSON，失败自动修复重试一次。
- 支持的图表集合为**因果图、判定表、正交表**（黑盒三件套），状态迁移图等留到二期。
- 图表到用例的转换采用**确定性推导**：因果图 → 判定表，判定表/正交表 → 用例骨架；因果图不直接产出用例骨架。
- 用例骨架本期**走接力到现有 AI 用例管线**：骨架序列化为结构化文本，与需求原文一起写入 `REQUIREMENT_HANDOFF_KEY`，跳转到用例生成工具时预填新建用例弹窗；不直接落库为正式用例。
- 画布内容（图元数据 + 布局）以 JSON 形式**持久化到分析记录新增的 `board` 字段**，自动保存防抖 1.5s；版本字段 `version` 为后续迁移留入口。

## 备选方案

- **SVG/DOM 混合渲染**：命中检测与交互基本由浏览器"白送"，但表格与自由图元混合布局在复杂场景下性能与一致性差，且用户已明确拍板 Canvas 路线，否决。
- **多页签或分区画布**：把不同图表放在不同页签或固定分区，结构清晰但违背"自由白板"对标方向，否决。
- **用例骨架直接落库**：不经过 AI 用例管线而直接写入测试用例集，可缩短路径但会破坏现有覆盖模式、质量校验与编号体系，首期选择保持接力，二期再评估直接落库。

## 后果

- `MindMapView` 与 `TreeChartView` 退役：需求树在画板上以 `mindmap-ref` 只读图元由 Canvas 重绘，原组件及其测试随本期删除。
- 分析记录 schema 新增 `board?: Board` 字段；旧记录缺失该字段时视为空白板；`PATCH /records/:id` 扩展为自动保存通道。
- 画板顶部不再保留图表类型切换菜单；左侧工具栏替换为插入因果图/判定表/正交表的入口，模板中心入口保留但二期再接真正插入。
- 右侧"生成测试用例"按钮含义升级：从仅接力需求原文，升级为"需求原文 + 画布上判定表/正交表导出的用例骨架"。
- 二期候选能力记录在 spec §11：状态迁移图、覆盖率追溯矩阵、因果图完整性体检、判定表合并简化、正交因子智能推荐等。
