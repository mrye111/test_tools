# 0005 — 分析画板取代需求分析结果页与图表画布浮层

> 本文已被 [0006](0006-analysis-board-dedicated-route.md) 修订：画板改为独立路由 `/requirement-analysis/board/:id`（URL 直达、先存后跳），并移除"重新分析"入口。下文保留画板布局与模板中心骨架的原始决策。

## 状态

已接受（部分被 0006 修订）

## 背景

ADR 0004 落地"记录列表 ↔ 结果视图"两层结构后，结果视图是传统的面板式布局（顶部工具栏 + 图表区 + 结论面板 + 底部折叠区），另有一个从结果页进入的全屏"图表画布"浮层（ChartCanvasModal）。两套结果视图并存，选中节点、图表类型、结论面板等状态需要双向同步。用户提出以 boardmix 白板编辑器为参考，打开记录即进入全屏画板，并预留后续"插入模板"等白板能力的入口。

## 决策

- 结果视图的形态改为**分析画板**：打开记录或新分析完成后，直接进入全屏画板；旧结果页布局与图表画布浮层（ChartCanvasModal）整体退役。
- 画板布局：画布中央渲染当前分析结果图表；顶部左侧为返回列表与记录名称，顶部中央为图表类型切换下拉框；右侧为竖向无文案图标工具栏（接力生成用例、导出 XMind/FreeMind/Markdown/PNG、重新分析、结论面板开关、关闭画板）；左侧为可收缩竖向工具栏，第一个工具为"插入模板"；缩放控制条悬浮于画布右下角；解析原文与分析过程收进画板底部唤起的抽屉；警告以画板顶部可关闭横幅展示。
- 分析画板本期仍为只读阅览形态：缩放/平移/适应屏幕复用渲染器原生能力（markmap d3-zoom / ECharts roam），不支持编辑需求分解树结构。
- 插入模板本期只做模板中心窗口骨架：左侧分类导航 + 右侧模板卡片网格，模板数据为内置静态列表，"使用模板"暂不真正插入画布（画板尚无可插入的对象模型）。
- 术语表同步修订：新增"分析画板"词条，取代"图表画布"。

## 备选方案

- **画板叠加在旧结果页之上**：两套结果视图长期并存，状态同步成本翻倍，且顶部下拉、左右工具栏本质就是新结果页骨架，否决。
- **模板插入一步到位（真插入）**：依赖画板可编辑对象模型，工程量越出本期"先把画布开发出来"的范围，否决；模板中心骨架为后续迭代预留入口。

## 后果

- "记录列表 ↔ 结果视图"两层结构语义不变，结果视图形态换成画板。
- ChartCanvasModal 组件及其测试退役，能力并入 AnalysisBoard。
- 后续做可编辑画板时，模板中心的"使用模板"动作才有落点；该入口的形态与导航结构本期已固定。
