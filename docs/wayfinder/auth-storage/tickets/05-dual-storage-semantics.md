## Question

模型配置「本地 / 云端」双存储的语义全案定稿（HITL，用 /grilling + /domain-modeling 逐题拍板）：

1. **local→cloud 切换语义**：复制上云并删本地？保留双份？反之 cloud→local 呢——切换是「搬运」还是「改变归属」
2. **云端配置在本机是否留缓存副本**：离线 / 断网时能不能用
3. **activeModelId（当前生效配置）**归浏览器还是归用户
4. **未登录时对云端配置的可见性**（强制门禁下预期完全不可见——确认之）
5. **多设备并发编辑同一云端配置**的冲突调和：乐观锁？last-write-wins？还是先不管（如实记录）
6. **云端配置回显掩码**与「测试连接」等操作的密钥使用规则

前提（建图已拍板）：每条配置自带本地/云端开关、默认本地；云端挂当前登录用户、密钥入库加密；业务数据全库共享。

## Resolution

五题逐项拍板后经用户确认的定稿全集：

1. **切换 = 迁移**：开关拨的是「这条配置住在哪」——拨云端 = 上传后删本地，拨回本地 = 下载后删云端。任一时刻一条配置只有一个家，列表永无双份。
2. **云端配置零本地存在**：不留缓存副本，用时实时从服务端取；未登录完全不可见。依据：强制门禁 + 全量入库下应用不存在离线模式，缓存只会白添「过期同步 + 客户端又落一份密钥」两重麻烦。
3. **activeModelId 归浏览器**：生效选择留在本机（随本地配置域豁免入库，与「配置默认本地」的建图豁免自洽），每台机器各选各的；指向的配置不存在时自动回退本机可用列表第一条。
4. **并发编辑乐观锁**：每条云端配置带版本号，更新走条件 UPDATE，冲突返回 409「已被其他设备修改，刷新后重试」——密钥不容被旧值静默回滚。
5. **密钥回显按归属画线**（以「密钥过没过网络进服务端」为界）：
   - 云端配置：保存后永不再回显明文（掩码如 `sk-***f8`）；编辑时留空 = 保持不变；「测试连接」由服务端代发，密钥不出服务端。
   - 本地配置：维持现状（明文存自己浏览器，可看可改，归用户自管）。

**雾区裁决**：地图雾区「多设备云配置冲突调和细则」已由第 4 条一锤定音（乐观锁一列版本号即够），无需拆票，已从雾区清除。
