## Question

小偏好入库后的归属与瞬态排除清单定稿（HITL，用 /grilling 逐题拍板）：

1. **URL 记忆类归属**：`ai-run-entry:*`（用例生成入口 URL 记忆）、自动化导入入口 URL 记忆——入库后按用户存还是全库共享？（业务数据共享，但「习惯」可能该跟人走）
2. **瞬态排除清单终稿**：需求接力载荷之外，还有没有应排除、不该入库的瞬态项（草稿、未提交表单态等）？
3. **「本地/云端可选」待遇的适用面**：模型配置之外还有没有别的数据该享受同样的双存储选择？

前提（建图已拍板）：一切非数据库持久化数据入 MySQL（瞬态除外）。

## Resolution

三题逐项拍板后经用户确认的定稿全集：

1. **个人偏好按用户存**：两个入口地址记忆（`ai-run-entry:*` 用例生成入口、`requirement-import-entry-*` 自动化导入入口）入库后挂用户，各记各的习惯，互不覆盖。选它的依据：这是「习惯」不是业务事实——两个测试员对同一目标各用各的环境地址（测试服/预发服）是常态，共享会互相覆盖。**前提修订**：「挂用户的数据」由「仅云端模型配置」扩为「云端模型配置 + 个人偏好」（CONTEXT.md 已同步修订）。
2. **瞬态排除清单终稿（就两项）**：① 需求接力载荷（读后即删的跨页载荷）；② 需求分析任务的进程内缓存（`jobs.ts`，本就不持久化）。除此之外一切持久数据全量入库（票 03 盘点已穷尽，别无遗漏）。
3. **双存储待遇只给模型配置**：个人偏好入库、无开关；自动化凭据天然住服务端（服务端执行器要取用，「本地」无意义）；业务数据全库共享、无归属可言。开关是模型配置的领域特性（密钥 + 多供应商），不外溢。
