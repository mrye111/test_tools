## Question

登录 / 注册的交互与政策定稿（HITL，用 /grilling + /domain-modeling 逐题拍板）：

1. **注册字段与密码规则**：用户名还是邮箱还是两者？密码强度要求？
2. **登录 / 注册 / 登出的界面位置与形态**：独立页还是弹窗？未登录访问任意路由的跳转行为？
3. **首个用户自动管理员的语义**：管理员能力边界（至少含「关闭注册」；其余边界可随手记入雾区）
4. **注册开关**：谁关、存在哪；关闭后新人怎么进（邀请 / 管理员建号——触到雾区即可，不必展开）
5. **改密 / 找回密码要不要**：若要找回，对外触达通道（邮件等）可能触发范围讨论，如实记录
6. **账号停用要不要**
7. **登录形态是否止于账号密码**：SSO / 扫码要不要——未表态则默认否

前提（建图已拍板）：强制登录门禁；开放自助注册；首个注册用户自动成为管理员；多用户、业务数据全库共享，仅云端模型配置挂用户。

## Resolution

七题逐项拍板后经用户确认的定稿全集：

1. **凭据与注册字段**：用户名（唯一）+ 密码，不收邮箱；密码规则按 NIST SP 800-63B-4（研究票 01）：15–64 字符、不强制大小写/符号组合、拒绝常见泄露口令黑名单。
2. **界面形态**：独立 `/login`、`/register` 页；未登录访问任意路由 → 重定向 `/login?redirect=原地址`，登录成功后回跳；登出入口在导航栏用户菜单。
3. **管理员**（首个注册用户自动成为）：能力边界=用户管理——注册开关、用户列表、创建账号（用户名+初始密码）、停用/启用、重置密码；对业务数据零特权。
4. **注册开关**：管理员关闭、入库保存；关闭后新账号只能由管理员创建。
5. **密码生命周期**：本人自助改密；忘记密码走管理员重置为新初始密码；无自助找回通道（无邮件/短信触达）。
6. **登录形态**：止于账号密码。SSO / OAuth / 扫码登录全部排除出本期（已列入地图 Out of scope；未来要做另立新图，届时研究票 01 留的 better-auth 后手可评估）。
7. **初始密码细则**（补提并确认）：管理员创建/重置出的初始密码**不强制**首次登录改密，登录后提示可改。
