## Question

单用例执行已通，下一步是批量回归。需要与用户敲定形态：

1. **批量粒度**：按「用例集」批量跑（自动化用例没有"集"的概念——是否给自动化用例引入用例集/标签分组？还是按项目+筛选条件批量？）；
2. **执行策略**：全局并发上限 3（已定）、失败是否继续（默认继续，记录每例结论）、执行缓存按套件共享 read-only 基线还是逐例 read-write（票据 03：CI 场景 read-only + 通过后 flush）；
3. **结果聚合**：套件运行报告形态——汇总页（N 通过/M 失败/K 部分 + 每例链接到单运行报告）放在运行历史里，还是生成独立"套件运行"记录；
4. **触发方式**：手动触发先行，定时/CI 触发是否本期范围（建议：本期手动，定时任务进 CI 集成雾区）。

依赖：票据 10 的统计结果（决定套件怎么分组最自然）。

## Resolution

2026-09-21 与用户定稿（四项全按推荐）：

- **分组容器：用例集**——自动化用例引入「用例集」层级，与功能用例的 项目⊃用例集⊃用例 三级模型对齐；批量转入（功能用例 → 自动化用例）时自动成集
- **执行策略：失败继续**——单例失败不中断套件，跑完全部并记录每例结论
- **缓存策略：逐例 read-write**——越跑越快；套件共享 read-only 基线留作未来 CI 场景选项
- **触发方式：手动触发**——套件「全部执行」按钮；定时任务/CI 进雾区

实现要点（执行时遵循）：套件运行生成 batchId 贯穿所有成员运行记录，聚合视图按 batchId 汇总（N 通过/M 失败/K 部分 + 每例链接）；并发仍受全局 3 + 同用例集缓存串行约束。
