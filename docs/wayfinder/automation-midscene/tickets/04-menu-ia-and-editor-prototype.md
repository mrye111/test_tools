## Question

「自动化测试」一级菜单的信息架构与关键页面，做出可点击原型供用户确认方向。覆盖：

1. **交互执行台**：URL + 自然语言指令输入、实时画面区（方案已定，见票据「Midscene 服务端集成与实时画面方案调研」Resolution：**MVP = 步骤状态推送 + `plan_thinking` 进度事件自带截图**，CDP screencast 真直播为后续增强；进度事件含 thought/action 起止/落点坐标，步骤流可直接渲染）、步骤流展示、「一键存为用例」入口；
2. **自动化用例管理**：用例列表（归属项目）、用例编辑器（结构化步骤：act/assert/query/wait + 变量占位 + 前置条件）、执行入口与执行参数（目标环境、是否用缓存）；
3. **运行历史与报告查看**：运行列表（状态/耗时/通过率）、单运行的逐步回放 + Midscene HTML 报告嵌入；
4. 与现有导航（Navbar「工具」菜单、首页工具矩阵卡片）的接入形态；
5. **如实呈现可自动化程度**（依据已关闭的票据「功能用例→AI 指令编译策略调研」：实测 38% 功能用例含非 UI 操作）——编辑器与执行结果必须区分可自动执行步骤与 manualItems，partial 用例不得呈现为"全部自动化通过"；编译产物执行前可预览、可手工修正。

原型用现有组件风格（参考 src/components/ui/ 与各 Page 的布局语言），可用静态 HTML 或项目内临时路由，重点是结构与交互流而非视觉完成度。产出链接给用户确认。

## Resolution

2026-09-21 用户评审通过原型（两轮迭代）。原型资产：[prototype/index.html](../prototype/index.html)（v2，ui-ux-pro-max 设计升级，四个关键界面已经浏览器渲染验证）。

定稿的信息架构（实施依据）：

- **导航**：顶部玻璃胶囊导航在「工具」与「文档」之间插入「自动化测试」一级入口（带 NEW 标）；首页工具矩阵同步加卡片
- **三主区**：用例管理（列表 + 可自动化程度列：●全自动 / ◐部分自动·N 项人工 / ○需人工禁用执行）· 交互执行台（URL+自然语言指令 → 深色执行状态条 + 画面区[plan_thinking 截图+点击落点] + 执行流[💭思考+动作耗时] + 一键存为用例）· 运行历史（统计卡：今日运行/通过率 gauge/平均耗时·缓存命中/待人工补执行；运行列表可展开步骤级回放 + Midscene 报告 iframe 嵌入）
- **用例编辑器**：结构化步骤（act/assert/extract/wait 类型色左边条 + ← 溯源 chip + `${变量}` 凭据占位 + `{{extract}}` 传值）；右侧深色 code 面板编译预览（原文↔产物对照可切换）+ ⚠需人工执行警示区（附原因）+ 执行参数（环境/引擎/缓存/重试）
- **用例页集成**：测试用例页加「执行」按钮 → 实时编译摘要（N 条指令 · M 项人工 · 入口 URL）→ 逐步直播 → 结果回写执行状态列；执行中 shimmer 状态可中止
- **设计纪律**：浅色底蓝调随宿主产品（拒绝设计系统推荐的深色底绿主色）；执行按钮用绿色 go/run 语义与品牌蓝区分；零 emoji 全 SVG 图标（24×24/stroke 2）；prefers-reduced-motion 全局降级

用户确认：信息架构、编译产物可手工修正的交互、设计方向——全部无异议。
