## Question

由票据「功能用例→AI 指令编译策略调研」结论毕业：对 MySQL 中全部存量功能用例（登录集 20 + 包年套餐集 95 + 新增用例集）跑一遍批量预编译，验证编译器在真实规模下的表现，并产出「可自动化率」统计报告。

1. 遍历全部项目 → 功能用例集 → 每条用例调 `/api/automation/compile`（走缓存，重复文本零成本）；
2. 聚合统计：full/partial/manual 占比、compileFailed（降级直映）占比、manualItems 原因分类（后端批处理/API 调用/日志检查/数据准备……）、校验错误 TOP N；
3. 产出报告（哪些用例集最适合优先自动化、manual 集中的原因模式、编译器 prompt 的改进线索）写入 Resolution，报告全文落 `docs/wayfinder/automation-midscene/research/`。

结论直接指导后续：哪些用例可以一键转入自动化资产、执行器 API 动作通道（雾区项）值不值得做。

## Resolution

2026-09-21 完成（**范围按用户要求收窄为「自动化测试」项目**，其他项目未编译）。

**结果（百度搜索用例集 34 条，编译 API 零失败、零降级直映、缓存机制验证有效）**：

| 评级 | 用例数 | 占比 |
|---|---|---|
| full（可全自动） | 19 | **56%** |
| partial（部分自动） | 15 | 44% |
| manual（需人工） | 0 | 0% |

**编译器质量**：34/34 一次编译通过校验（无 compileFailed），fromStep 溯源与 manualItems 标注在真实规模下工作正常。

**人工项原因分布**（59 项，含缓存中其他项目样本）三类模式清晰：
1. **API/服务调用发起**（"发起100条OPST调用""触发结算"）——**执行器 API 动作通道值得做**：这是套餐计费类用例 manual 的第一大来源，把这类步骤映射为可配置 HTTP 动作可显著降低 partial 率；
2. **系统/网络状态构造**（弱网限速/恢复、切换中文输入法）——超出浏览器边界，需外部工具或测试环境配合，不纳入自动化范围（如实保留人工项）；
3. **不可视觉判定的断言**（焦点状态、逐字符动态过程、"请求未发送"）——视觉断言的固有限制，部分可改写为 DOM/状态类断言（远期增强，非视觉引擎缺陷）。

**对票据 11（套件编排）的影响**：百度搜索集 56% 可直接全自动、44% 可半自动，无全人工——非常适合作为首个套件试点；用例集就是天然的套件分组（不必另建标签体系）。

工具沉淀：`server/scripts/batch-compile.mjs [apiBase] [projectFilter]`（项目过滤参数是用户要求后加的）。报告全文：[research/10-batch-compile-report.md](../research/10-batch-compile-report.md)。
