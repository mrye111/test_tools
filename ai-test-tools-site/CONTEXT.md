# CONTEXT

测试用例工具的领域术语表。只收录领域语言，不写实现细节。

## 术语

### 项目（Project）

测试用例的最高层归属单位，代表一个业务系统或产品线。项目是分组容器，本身不承载用例内容，但携带「被测系统地址」与「项目图标」两类项目级元数据。

### 被测系统地址（SystemUrl）

项目所测产品的真实入口地址。可选元数据，允许内网地址、IP 与 localhost；系统仅记录与外链展示，不探测可达性；未来 UI 自动化以其为执行基地址。

### 项目图标（ProjectIcon）

项目的视觉标识，由图标符号与配色两部分组成。图标符号取自内置图形隐喻图标或品牌标志图标；配色决定图标字形颜色，徽标底色为该色的同色系浅色调。不支持上传图片；新建项目默认「文件夹图标 + 主题蓝」。

### 用例集（TestSet）

一次生成或维护行为产出的用例集合，隶属于一个项目。通常对应一份需求文档，记录生成时的需求原文（context）、生成参数与状态。

### 用例（TestCase）

一条具体的测试用例，隶属于一个用例集。由功能模块、测试点、标题、优先级、前置条件、测试步骤、预期结果组成。

### 补充需求（Supplement）

对用例集做**纯增量追加**的维护行为：用户提供补充说明，AI 只生成已有用例未覆盖的新用例，**不修改、不删除任何已有用例**。

### 优化用例（Optimize）

对用例集做**整体改写**的维护行为：用户提供一段自然语言指令（如界面的实际操作逻辑），AI 基于指令返回完整新用例集，可修改、新增、删除用例，解决用例内容与界面实际操作逻辑不符的问题。与「补充需求」互斥：补充需求是纯追加，优化用例是整体改写。

### 测试类型（TestType）

用例集的类型：功能测试（functional）或 API 测试（api）。API 测试的用例列结构不同（接口名称、请求方式及路径替代功能模块、功能测试点），用例编号前缀为 API-TC。

### Swagger/OpenAPI 文档

API 测试用例集的可选生成依据，与需求描述并列。作为纯文本参与生成，系统不理解其语义；唯一例外是文档超限时，为拆分目的解析顶层 paths 结构，按接口分组分批生成后合并去重，结果仍是一个用例集。

### 参考文件（Reference File）

用户通过粘贴带入 AI 生成弹窗（添加测试用例集 / 补充需求 / 优化用例）的文档或图片，作为生成依据之一。解析器提取文本后以独立标记段并入 AI 上下文，与手写需求描述互补、不替代；解析失败或超长截断均在文件卡片上显式标识，不得静默丢弃。

### 用户（User）

系统的登录账号，以用户名（唯一）+ 密码登录，无邮箱字段。业务数据（项目/用例集/用例/报告等）全库共享、不按用户隔离；挂用户的数据是云端存储的模型配置与个人偏好（如入口地址记忆）。

### 模型配置存储归属（Local / Cloud）

模型配置二选一的存放处：**本地**（此浏览器 + 此账号，默认，两者任一变化即丢失；同浏览器不同账号互相隔离）或**云端**（挂当前登录用户，密钥入库加密）。按条自选，两种归属的配置可共存。归属切换是**迁移**：整条配置搬走（拨云端=上传删本地，拨回本地=下载删云端），任一时刻一条配置只有一个家。

### 管理员（Admin）

系统管理域的唯一特权角色，首个注册用户自动成为。能力边界仅限用户管理：注册开关、用户列表、创建账号、停用/启用账号、重置账号密码；对业务数据无任何额外特权（业务数据全库共享、无所有权概念）。

### 账号停用（Deactivation）

账号的软禁用状态：被停用账号不能登录，既有数据不受影响；管理员可重新启用。

## 关系与规则

- 三级包含关系：项目 ⊃ 用例集 ⊃ 用例。
- 删除项目是级联操作：项目下的用例集、用例及相关生成任务一并删除，不可恢复。
- 「编辑项目」维护项目名称、被测系统地址、项目图标与配色。
- 开放自助注册（可由管理员关闭）；首个注册用户自动成为管理员。
- 注册关闭后，新账号由管理员创建（用户名 + 初始密码）。
- 密码可由本人修改；忘记密码由管理员重置为新初始密码，无自助找回通道；初始密码不强制首次登录改密。
- 模型配置存储归属二选一：本地（默认）或云端（挂当前登录用户）；切换即迁移，不留双份。
- 云端模型配置不在浏览器留副本，登录后实时取用；未登录不可见。当前生效的模型配置按浏览器记忆，不随账号跨设备走。
- 云端模型配置的密钥保存后不回显明文（以掩码代替），测试连接由服务端代发；本地配置的密钥归用户自管。
- 个人偏好（入口地址记忆等）按用户入库，各记各的，不共享。

## 自动化测试（UI 自动化）

### 自动化用例（AutomationCase）

UI 自动化的独立资产，直接隶属于项目（不经用例集）。由结构化指令步骤（act/assert/extract/wait）、前置条件、变量占位（${VAR}，真实值只存服务端配置）与人工项（manualItems）组成。来源有三种：手工新建（manual）、执行台流程固化（playground）、功能用例导入（functional-import）。

### 编译产物（CompiledPlan）

功能用例（自然语言步骤+预期）经 LLM 预编译产出的可执行指令计划：原子指令序列（带 fromStep/fromExpected 溯源）、executable 评级、人工项标注。按用例文本 hash 缓存，文本变化自动重编；校验两次未过降级为逐条直映（A 模式）并标记 compileFailed。

### 可自动化程度（executable）

用例的自动化可行性评级：full（无人工项，可全自动）、partial（有可执行步骤亦有人工项，结论最高为"部分通过"）、manual（无可自动执行步骤）。由指令数与人工项数确定性推导，不采信 LLM 自报值。

### 人工项（manualItems）

浏览器 UI 自动化天然不可执行的操作（数据库读写、日志检查、API 调用、批处理触发等），编译期识别并附原因；执行时跳过并如实计入报告，不得呈现为已验证。

### 需求导入任务（Requirement Import）

把勾选的测试条件一次性贯通为自动化用例的编排行为：生成功能用例集 → 回写追溯矩阵 → 批量编译落库。中间产物保留为功能用例集（可导出、可人工审改），单条失败不中断整批，结果按可自动化程度分布汇总。追溯矩阵按「已生成功能用例」计覆盖，自动化用例落库情况单列不混入覆盖率。
